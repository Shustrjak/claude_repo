# Семантические компоненты (Уровень 4 — Component Logic)

Часть UI-спецификации Banking Shell. Список компонентов и примитивов — в [COMPONENT_INVENTORY.md](COMPONENT_INVENTORY.md).

Входные данные описаны **концептуально**. Это не TypeScript-типы: точные типы появятся вместе с API-контрактом (уровень 5).

---

## Правила

1. **Компонент не знает, на каком он экране.** Например, `PaymentConfirmation` знает сумму, получателя, комиссию и статус, но не знает, что он «на PAY-04».
2. **Компоненты не ходят за данными.** Данные и действия приходят через входные параметры. Адаптер вызывает только экран — через хук фичи (см. [UI_ARCHITECTURE.md](UI_ARCHITECTURE.md#границы-логики)).
3. **Бизнес-логики нет ни в одном компоненте.** Бизнес-логика — это правила вроде «хватает ли денег», «лимит превышен», «MPIN верный». Её результат приходит в компонент готовым: статусом или ошибкой.
4. **UI-логика допустима.** Это таймер, маска ввода, проверка формата поля, доступ к камере — то, что не зависит от банка.
5. **Намерение вместо подписи.** Компонент получает смысл (`action="confirm"`), а текст и иконку выбирает сам.
6. **Никаких универсальных компонентов.** Если у компонента появляются десятки несвязанных параметров, его нужно разделить.

**Тип логики** в карточках:

| Тип | Что значит |
|---|---|
| Отображение | Только показывает то, что получил |
| UI-логика | Хранит своё UI-состояние: таймер, фокус, проверку формата |

## ActionButton

| Поле | Описание |
|---|---|
| Назначение | Основная кнопка действия. Текст и иконка берутся из намерения |
| Входные данные | `action`, `disabled`, `loading`; `label` — только если нужно переопределить стандартную подпись |
| Состояния | Обычное, неактивное, загрузка |
| Варианты | По `action`, см. таблицу ниже. Вид (primary, secondary, link) задан для каждого намерения |
| События | `onPress` |
| Где используется | Все флоу, 13 экранов и состояний (матрица — в [COMPONENT_INVENTORY.md](COMPONENT_INVENTORY.md#матрица-переиспользования)) |
| Зависит от | `Button`, `Icon` |
| Тип логики | Отображение |

Таблица намерений. Подписи и иконки — предложение [A].

| `action` | Подпись | Иконка | Вид |
|---|---|---|---|
| `next` | Далее | Стрелка вправо | primary |
| `confirm` | Подтвердить | Галочка | primary |
| `pay` | Оплатить | — | primary |
| `retry` | Повторить | Круговая стрелка | secondary |
| `cancel` | Отмена | — | secondary |
| `close` | Готово | Галочка | primary |

- **Чего нет:** намерений под конкретный экран (`register`, `login`) и `logout`. Выход — это строка `ListRow(danger)` в настройках.
- **Как расширять:** новое намерение добавляется, только если оно встречается хотя бы в двух флоу.
