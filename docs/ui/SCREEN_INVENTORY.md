# Инвентарь экранов (Уровень 1 — Screen Map)

Часть UI-спецификации Banking Shell. Общая схема — в [UI_ARCHITECTURE.md](UI_ARCHITECTURE.md).

**Источник:** схема User Flow из референса R38, файл [`refs/R38-user-flow.jpg`](../../refs/R38-user-flow.jpg).
На схеме платежи сделаны на UPI (Индия). По решению [D-01] UPI заменён на **СБП**: подписи узлов на схеме остались английскими, а ID и названия экранов — уже под СБП.
Всё, чего нет на схеме, помечено как `UNKNOWN` или `[A]`. Такие пункты не считаются требованиями.

**Легенда:**

| Метка | Значение |
|---|---|
| `[S]` | Взято из схемы |
| `[A]` | Допущение или предложение, требованием не является |
| `[R]` | Взято из [`ROADMAP.md`](../../ROADMAP.md), на схеме этого нет |
| `[D-xx]` | Принятое решение. Журнал решений — в [UI_ARCHITECTURE.md](UI_ARCHITECTURE.md#журнал-решений) |
| `UNKNOWN` | Схема этого не описывает |
| `SOURCE_REQUIRED` | Экран существует на схеме, но его содержимое не проектируется, пока нет источника (Q-11, [D-07], [D-20]) |

**Статусы экранов:**

| Статус | Значение |
|---|---|
| `CONFIRMED` | Узел схемы, который является экраном. Содержимое при этом может быть неизвестно |
| `CANDIDATE` | Узел схемы, который не подтверждён как экран. Сейчас это только SBP-02 — группа навигации с неизвестным содержимым (Q-11) |
| `NAV_ITEM_DISABLED` | Отключённый пункт навигации без экрана: показывается неактивным, композиции и данных нет. В число экранов не входит ([D-11]) |
| `CANDIDATE / NAVIGATION GROUP` | Кандидат, который скорее группа пунктов навигации, чем экран (SBP-02) |
| `DUPLICATE` | Повтор узла, который уже учтён. Отдельного экрана не получает |
| `FLOW_NODE` | Не экран: начало, решение, переход, действие, метка ребра |
| `EXCLUDED` | Узел схемы, исключённый решением. ID не получает (N45, [D-06]) |

## 2. Сводка по экранам

- **Всего ID экранов: 30.**
  - **CONFIRMED — 29:** AUTH-01…07, HOME-01…04, ACC-01, ACC-02, ACC-03, ACC-07, PAY-01…04, PAY-06, SBP-01, SBP-03, CARD-01, SVC-03, NOTIF-01, SET-01…04. Из них у 9 содержимое — SOURCE_REQUIRED (Q-11, [D-20]): HOME-02, HOME-03, ACC-01, ACC-03, PAY-01, PAY-02, CARD-01, SVC-03, NOTIF-01.
  - **CANDIDATE — 1:** SBP-02 (группа навигации, содержимое — SOURCE_REQUIRED).
- **Отключённые пункты навигации [D-11] — 6, не экраны:** ACC-04, ACC-05, ACC-06, SVC-01, SVC-02, SVC-04. ID сохранены, чтобы на них можно было ссылаться. См. [раздел 3.2](#32-отключённые-пункты-навигации).
- **Исключён [D-06]:** N45 Pay to UPI ID (бывший PAY-05). ID PAY-05 больше не используется.
- **Дубли** (узлы без своего ID): N29 → CARD-01, N35 → PAY-01, N36 → PAY-03.
- **Не экраны:**
  - N01 Start;
  - решения D1 (N02) и D2 (N03) — по [D-08] это действия на AUTH-01, отдельного экрана нет;
  - переход N11 «Take user to home page»;
  - действие N42 Logout;
  - глобальный компонент N19 Bottom Navigation Bar;
  - пункт навигации N34 Go to Home;
  - метки рёбер YES, NO, Success, Failure.
- **Откуда 30.** В исходном списке задачи 36 экранов. Добавлен узел N38 **UPI Functions** (теперь SBP-02), убран Pay to UPI ID [D-06], шесть кандидатов стали отключёнными пунктами навигации [D-11].
- **Переименования по [D-01] и [D-04]:** PAY-07 UPI → **SBP-01 СБП**; PAY-09 UPI Functions → **SBP-02 Функции СБП**; PAY-08 Register UPI → **SBP-03 Подключение СБП**. СБП — часть домена платежей (PAY), отдельным бизнес-доменом не считается.
- **Зарезервированные разделы [D-05]:** кредитная карта, кешбэк и накопления. Экранов пока нет, см. [раздел 3.1](#31-зарезервированные-разделы).
- **Состояния флоу.** PST-01 — подтверждение платежа и PST-02 — результат платежа обязательны по [D-13]; PST-03 — ошибка входа, предложение. ID экранов они не получают, описаны в [USER_FLOWS.md](USER_FLOWS.md#состояния-флоу).

## 3. Карточки экранов

Формат карточки:

| Поле | Что в нём |
|---|---|
| Узел | Номер узла на схеме |
| Вход | Откуда пользователь попадает на экран |
| Выходы | Действие → экран назначения |
| Поля | Поля формы, если они заданы решением (AUTH-02, AUTH-05 — [D-15]) |
| Содержимое | `SOURCE_REQUIRED`, если содержимое экрана не проектируется без источника (Q-11) |
| Общие компоненты | Семантические компоненты из [SEMANTIC_COMPONENTS.md](SEMANTIC_COMPONENTS.md), используются и на других экранах |
| Уникальные | Компоненты, которые используются только здесь |
| Состояния | Важные состояния экрана |
| Вопросы | Ссылки на открытые вопросы |

`AppShell` и `AppHeader` есть на каждом экране, в карточках они не повторяются.

### PAY — платежи и СБП

По [D-04] Pay, СБП и Функции СБП — три навигационных узла одного домена платежей:

```
Платежи (PAY)
├── PAY-01 Pay                (входы: нижняя навигация, меню; содержимое — SOURCE_REQUIRED)
├── PAY-02 Bill Payments      (содержимое — SOURCE_REQUIRED)
└── SBP-01 СБП
    ├── PAY-03 Scan QR
    ├── PAY-04 Pay to Mobile Number
    └── PAY-06 Pay to Bank Account  (по реквизитам, остаётся в СБП [D-06])
SBP-02 Функции СБП            (нижняя навигация, кандидат / группа навигации)
SBP-03 Подключение СБП        (после входа, из SBP-01 [D-08, D-17])
```
