## 1. Что это за проект

**Banking Shell** — pet-проект: интерфейс мобильного банка, у которого банковское ядро заменяемое. Интерфейс работает только через интерфейс `BankingAdapter` и не знает, откуда берутся данные. Своего бэкенда нет.

- Карта экранов — схема R38 ([`refs/R38-user-flow.jpg`](../refs/R38-user-flow.jpg)), адаптированная под Россию и СБП [D-01].
- UI-кит — Альфа core-components (R30).
- Ядро сейчас: `DemoAdapter` (демо-данные из JSON, состояние в `localStorage`) или `NullAdapter` («ядро не подключено»).

## 2. Как запустить

```bash
npm install
npm run dev         # http://localhost:5173 → /login
npm run typecheck
npm run lint
npm test            # 285 тестов в 19 файлах
npm run build
```

Демо-вход: MPIN `1234`. Демо-коды OTP и почты: `123456`.

## 4. Стек

React 19 · TypeScript 6 (strict, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`) · Vite 8 · react-router 8 · Vitest 5 + Testing Library + user-event на jsdom · ESLint 9 (typescript-eslint strict, react-hooks) · `@alfalab/core-components-*` отдельными пакетами (точные версии) · `@alfalab/icons-glyph`.

Сознательно **не** используются: Redux, Zustand, TanStack Query, DI-фреймворки, i18n-библиотеки, библиотеки дат. Причина — для текущего объёма хватает локального состояния, контекстов и `Intl`.

## 7. Архитектура — главное

1. **Две границы, обе заменяемые.** `BankingAdapter` — банк (19 операций, `Result<T>` с `ContractError`, 11 кодов ошибок). `DeviceCapabilityAdapter` — устройство (биометрия, SIM). Выбор реализаций — только в `src/main.tsx`.
2. **Слои UI.** Примитивы Alfa → семантические компоненты (знают только свойства, не знают адаптера, маршрутов и ID экранов) → экраны (вызывают адаптер) → приложение (провайдеры, маршруты).
3. **Сессия** — в памяти (`AppSession`). Перезагрузка ведёт на AUTH-01. Выход закрывает сессию при любом ответе банка [D-44].
4. **Что хранится в браузере.** `banking-shell:demo-adapter:v1` — состояние `DemoAdapter`. `banking-shell:app-preferences:v1` — `{ version: 1, biometricLoginEnabled }` [D-35]. Больше ничего: MPIN, личные данные и язык приложение само не хранит.
5. **Язык** [D-49, D-50]: настройку хранит банк (`getLanguageSettings` / `setLanguage`). `LanguageProvider` загружает её один раз после входа. До входа и после выхода интерфейс на русском. Словари типизированы: пропуск текста в `en` — ошибка компиляции.
6. **Счета** [D-47, D-51]: главная показывает все счета в порядке адаптера; «основного» или выбранного счёта нет. Счёт для ACC-02 передаётся только адресом.
7. **Ошибки** превращаются в состояние экрана; сырые коды пользователю не показываются. Помощники статусов получают словарь и переводят ошибку при отрисовке.
8. **Регистрация** — контекст флоу в памяти; данные регистрации хранит адаптер, а не интерфейс.

## 12. Правила работы, которые соблюдались

Их стоит перенести в новый проект (например, в `CLAUDE.md`), чтобы работа шла так же:

- Документация главнее предложений в запросе. Экраны, поля и смыслы не выдумываются: неизвестное остаётся UNKNOWN, вместо догадки записывается вопрос Q-/CQ-.
- Каждое решение — в журнал со следующим свободным D-номером (сначала проверить журнал), отдельным коммитом **до** кода.
- `BankingAdapter` заморожен: 19 операций; новые операции — только через решение по контракту.
- Нет экранов-заглушек, нет ID экранов в банковском коде, нет глобальных стейт-библиотек без необходимости, нет DI-фреймворка.
- MPIN не логируется и не хранится: не в URL, не в состоянии навигации, не в контексте, не в `localStorage`/`sessionStorage`. Личные данные регистрации не сохраняются. Реальные WebAuthn и SIM API не используются.
- Временные отладочные страницы не коммитятся.
- После каждого шага: `typecheck`, `lint`, `test`, `build`, запуск `dev`, ручная проверка в Chromium. Не заявлять проверок, которые не запускались.
- Следующий шаг не начинать, пока о нём не попросили. Отчёт — по пунктам, вопросы — готовым блоком для копирования.

## 13. Как перенести проект

1. Весь код и документы — в git. Достаточно перенести репозиторий с историей:
   ```bash
   git clone <старый репозиторий> banking-shell
   cd banking-shell
   git checkout claude/sweet-dirac-ofjaqi
   git remote set-url origin <новый репозиторий>
   git push -u origin claude/sweet-dirac-ofjaqi
   ```
   Можно сделать эту ветку основной (`main`) в новом репозитории.
2. Не переносить: `node_modules/`, `dist/` — они создаются заново командами `npm install` и `npm run build`.
3. После переноса проверить: `npm install && npm run typecheck && npm run lint && npm test && npm run build` — ожидается 285 зелёных тестов.
4. Для новой сессии с ассистентом дать на вход этот файл и попросить прочитать документы из раздела 3.
